# 主链路节点六问

> 配合《第二次项目复盘.md》第一遍使用：对 12 个节点逐个回答六个问题。
> 读法建议：先只看「输入 → 输出」这一行，把这些串成一条链；再回来看「不能删掉它」，
> 因为那一栏才是设计理由，面试时真正会被追问的是它。

---

## 0. 一条贯穿全链路的规律

每个节点的**输出**就是下一个节点的**输入**，而且类型一路上都在变：

```
自然语言 → 知识文档 → 结构化意图 → 查询计划 → SQL → 带权限的 SQL → 结果行 → JSON → 日志
```

「为什么不能删掉它」的答案几乎都是同一个句式：**删了它，链路会退回到某个具体的坏状态。**
下面每一栏都写清那个坏状态是什么。

---

## 1. 运营人员输入问题（Web 前端）

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 人类入口：把「想问什么」变成系统能收的字符串，并带上身份令牌 |
| 输入 | 运营人员在输入框里打的自然语言 |
| 输出 | `POST /ask`，body `{question, previous_question?}`，Header 带 `X-API-Key` |
| 上游 / 下游 | 上游 = 人；下游 = Nginx |
| 出错或不支持 | 空串或超过 500 字 → FastAPI 返回 422（`app/api/main.py:29` 的 `Field` 约束） |
| 为什么不能删 | 删了就只剩 API，运营人员（非技术用户）无法使用，产品不成立 |

对应文件：`web/index.html`、`web/app.js`

## 2. Nginx 统一入口

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 唯一对外端口 + 反向代理，应用容器不直接暴露公网 |
| 输入 | 浏览器发到宿主 `8080` 的 HTTP 请求 |
| 输出 | 转发到 `http://ai-analytics:8000`，并补上 `X-Real-IP`、`X-Forwarded-For` |
| 上游 / 下游 | 上游 = 浏览器；下游 = FastAPI |
| 出错或不支持 | 后端没起来时 `depends_on: service_healthy` 保证 Nginx 不会先于后端可用；`proxy_read_timeout 90s` 到点断开 |
| 为什么不能删 | FastAPI 的 8000 端口会直接暴露；也失去统一做 HTTPS、限流、访问日志的位置 |

对应文件：`deploy/nginx.conf`、`docker-compose.yml`

## 3. FastAPI 认证（验证身份）

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | **你是谁**（认证）。注意：它不回答「你能看哪些数据」——那是第 8 步 |
| 输入 | 请求头里的 `X-API-Key` |
| 输出 | `Principal(name, role, shops)`；认不出来返回 `None` |
| 上游 / 下游 | 上游 = Nginx；下游 = DeepSeek 解析器 + QuestionService |
| 出错或不支持 | 令牌无效 → 401；未配置任何令牌时按匿名处理 |
| 为什么不能删 | 删了任何人都能查任意店铺；身份是后面所有权限判断的前提 |

对应文件：`app/auth.py`、`app/api/main.py:124-158`

## 4. RAG 检索（数仓知识）

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 问题变复杂后，只召回相关的指标 / 表 / 口径 / 示例，压低 Prompt 长度和选错指标的概率 |
| 输入 | 原始问题字符串 |
| 输出 | Top-8 知识文档（`RetrievalHit`），拼进 Prompt——**不是查询结果** |
| 上游 / 下游 | 上游 = 问题；下游 = DeepSeek（作为上下文） |
| 出错或不支持 | 一条都没召回 → 返回空列表，DeepSeek 仍能解析，最坏落到「unsupported」或澄清 |
| 为什么不能删 | 删了就得把所有指标口径和表结构硬塞进 Prompt：贵，而且模型更容易选错指标 |

对应文件：`app/retrieval/keyword.py`、`app/metadata/loader.py`

## 5. 大模型（DeepSeek）解析成结构化意图

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 把无限种自然语言问法**归一化**成同一套标准槽位（不同说法 → 同一个标准词） |
| 输入 | RAG 检索到的数仓知识 + 原始问题（追问时还带上一轮问题） |
| 输出 | `QuestionIntent`（metric / metrics / dimensions / time_range / sort / limit / filters）——**不是 SQL** |
| 上游 / 下游 | 上游 = RAG；下游 = 查询规划器 |
| 出错或不支持 | 信息不足 → `needs_clarification=True`，直接返回澄清，不往下走；模型接口挂了 → 500 |
| 为什么不能删 | 删了就退回关键词匹配，覆盖不了同义问法和「指标+维度+时间+排序+TopN」的组合表达 |

对应文件：`app/intent/deepseek.py`、`app/intent/bailian.py`、`app/intent/models.py`

## 6. 查询规划器（语义校验 + 选数据集）

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 判断**能不能查**（语义校验）和**去哪张表查**（数据集选择） |
| 输入 | `QuestionIntent` |
| 输出 | `QueryPlan`（dataset / time_field / metrics / dimensions / 指标表达式）；不合法就抛异常 |
| 上游 / 下游 | 上游 = 意图；下游 = 通用编译器 |
| 出错或不支持 | 缺时间 → `QueryClarificationNeeded` → 澄清；指标不在能力矩阵、或组合不安全（如订单数按店铺聚合）→ `QueryPlanningError` → 「unsupported」 |
| 为什么不能删 | 删了模型可以指向任意表和字段，白名单形同虚设；「订单数不能按店铺汇总」这类业务规则也没有地方安放 |

对应文件：`app/query_planning/planner.py`、`metadata/query_capabilities.yaml`

## 7. 通用编译器生成受控 SQL

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 把 `QueryPlan` 翻译成可执行 SQL（SELECT / WHERE / GROUP BY / HAVING / ORDER BY / LIMIT） |
| 输入 | `QueryPlan` |
| 输出 | SQL 字符串——**逻辑上正确，但还没有权限边界** |
| 上游 / 下游 | 上游 = 规划器；下游 = 权限注入 |
| 出错或不支持 | 计划里有编译器不支持的组合 → `ValueError` → 「unsupported」 |
| 为什么不能删 | 删了就退回「一题一个 SQL 模板」：11 指标 × 5 维度 × 8 时间范围的组合爆炸，模板写不完 |

对应文件：`app/query_planning/compiler.py`、`app/sql/generator.py`

## 8. 注入授权店铺范围（行级安全）

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | **你是谁 → 你能看见哪些行**。业界学名：行级安全（Row-Level Security） |
| 输入 | 编译器产出的 SQL + `principal.shops` |
| 输出 | 加了 `WHERE shop_code IN (...)` 的 SQL |
| 上游 / 下游 | 上游 = 编译器；下游 = 查询执行器 |
| 出错或不支持 | 非管理员且没配店铺 → 403；SQL 用到的表不支持按店铺隔离（如跨店品牌汇总表）→ 403「当前指标暂不支持按店铺授权查询」；店铺名含引号或换行 → 403 |
| 为什么不能删 | 删了运营能看见全公司数据。这是整条链路上**唯一一处由可信后端强制、绕不过去的**数据边界 |

对应文件：`app/questions/service.py:131-148`

## 9. 查询执行器（AST 安全校验 + 方言翻译）

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 收到 SQL 后先**再校验一遍**（AST），再翻译成目标引擎方言，然后提交 |
| 输入 | 注入权限后的 SQL + `max_rows` |
| 输出 | 提交给 MaxCompute / DuckDB 的连接，最终返回 `list[dict]` |
| 上游 / 下游 | 上游 = 权限注入；下游 = MaxCompute / DuckDB |
| 出错或不支持 | AST 校验不过（读了文件、跨库、非白名单表/字段）→ `QueryError`；超过 60 秒 → `QueryError` |
| 为什么不能删 | 校验放在 `execute()` 内部才**绕不过去**——任何调用执行器的路径都必须过这一关；方言差异也只有这里懂 |

对应文件：`app/query/maxcompute_runner.py`、`app/query/local_runner.py`、`app/query/sql_security.py`

## 10. DuckDB 或 MaxCompute 执行，返回数据行

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 真正的计算。**数值的唯一合法来源** |
| 输入 | 方言转换后的 SQL 字符串（不是执行器本身——执行器始终留在应用容器里） |
| 输出 | 结果集；MaxCompute 侧先物化，再通过 Tunnel 拉回本地 |
| 上游 / 下游 | 上游 = 执行器；下游 = 执行器（拿回 rows） |
| 出错或不支持 | SQL 语法错、表不存在、超时 → 抛异常 → 执行器包装成 `QueryError` → 500；写操作在更前面的 AST 层就被拦掉 |
| 为什么不能删 | 这是唯一能算出真实数值的地方。大模型不允许编数字，所以这一环没有替代品 |

对应文件：`app/query/maxcompute_runner.py:67-75`

## 11. 回答 / 结果组装

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 把结果行、指标口径、数据时间和 SQL 打包成统一回答结构 |
| 输入 | rows、intent、指标口径、SQL、检索上下文 |
| 输出 | `AnalyticsAnswer`（status / message / metrics / metric_definition / rows / sql）→ JSON |
| 上游 / 下游 | 上游 = 查询执行器；下游 = 前端 `app.js` |
| 出错或不支持 | 这一步本身基本不出错；它同时承担把「澄清」「拒答」也组装成同一种结构返回的职责 |
| 为什么不能删 | 删了前端只拿到裸 rows，用户看不到口径和数据时间，数字没法被信任 |

对应文件：`app/questions/models.py`、`app/questions/service.py:119-127`

## 12. 记录审计日志与监控指标

| 问题 | 回答 |
| --- | --- |
| 解决什么问题 | 事后可追溯（谁、什么时候、查了什么、给没给）和运行时可观测（量、耗时、状态分布） |
| 输入 | 每次请求的问题、状态、返回行数、耗时、身份与店铺范围 |
| 输出 | `logs/audit.jsonl`（追加写）+ `/metrics` 的 Prometheus 文本 |
| 上游 / 下游 | 上游 = 主链路各节点；下游 = 运维和排障，没有下游消费者 |
| 出错或不支持 | 未知状态会被强制归类成 `error`，避免指标出现无限多的标签值 |
| 为什么不能删 | 出问题无法定位（不知道是哪类问题、哪个账号、哪个店铺范围），也无法证明越权确实被挡住了 |

对应文件：`app/audit.py`、`app/metrics.py`、`app/questions/service.py` 的 `_audit`

## 附：三个最容易讲错的点

1. **FastAPI 的认证 ≠ 店铺权限。** 第 3 步只回答「你是谁」，第 8 步才回答「你能看哪些行」。
2. **RAG 的输出是知识，不是数据。** 它给模型的是「有哪些指标、口径是什么、该用哪张表」，
   真正的数值只能在第 10 步产生。
3. **大模型做的是归一化，不是提取关键字。** 「最近 30 天销售额排名前 3 的店铺」里，
   只有 `limit=3` 是原文有的，`sort=descending` 是推断出来的。
